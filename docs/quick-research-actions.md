# 在 GitHub 网页生成研究包

无需本地安装 Python，也无需 API 密钥。在仓库中打开 **Actions → 快捷股票研究（只读行情）→ Run workflow**。

1. 选择包含本工作流的分支；合并后通常选择 `main`。
2. 填写 1–5 只 A 股代码，例如 `000776.SZ, 000001.SZ`，用空格或逗号分隔。
3. 选择 `sina` 或 `eastmoney` 行情来源；不会在失败时自动换源。
4. 两个日期同时留空时，使用北京时间截至昨日的最近 21 个自然日；也可同时填写历史起止日期，窗口最多 366 天，结束日必须早于北京时间当天。
5. 点击 **Run workflow** 即允许本次只读获取公开供应商日历和行情。运行结束后，查看摘要并下载 **Artifacts → quick-research-运行编号**。

下载的 artifact 内包含 `research.zip`（生成且校验通过时）、`verification.json` 和 `action-result.json`。先解压 artifact，再解压 `research.zip`，打开其中的 `index.html` 查看研究页面、采集来源和日期诊断。artifact 保留 7 天。

运行摘要和 `action-result.json` 的 `package` 字段记录内层 `research.zip` 的文件大小及 SHA-256。转存后可在 Windows PowerShell 中运行 `Get-FileHash .\research.zip -Algorithm SHA256`，与原运行摘要的值核对。

运行摘要直接显示逐股处理结果；`action-result.json` 保存本次运行的固定原因码、中文消息、计数和逐股结果。依赖不可用、输入或生成校验失败、执行或输出失败会分别标记，但不会输出原始异常内容。此运行结果与 `verification.json` 的文件完整性结论分别记录；没有 ZIP 的失败诊断不代表已生成研究。

通过输入校验并准备好本次输出目录后，摘要及 `action-result.json` 的 `request` 字段会记录本次股票列表、显式行情源和实际起止日期；原输入留空的日期会显示为解析后的具体日期。即使后续采集或校验失败，也会保留该请求记录，方便核对本次运行窗口。无效输入或拒绝复用旧目录时不会生成新的请求产物。

部分或全部股票未生成研究时，摘要会列出仅包含未完成股票的 **Run workflow 重跑参数**；`action-result.json` 的 `rerun_request` 保存相同字段。复制 `symbols`、`upstream`、`start_date`、`end_date` 到新的手动运行即可，已生成股票不会被重复加入。即使原运行日期留空，这些参数也固定为原运行实际使用的日期窗口，不会随重跑日期向前滚动。

重跑始终由你手动触发，不会自动换源或增加后台调用。日期待核查项应先检查日历与返回日期；相同窗口重跑不保证解决日期差异。全部成功时不提供重跑参数；没有研究包、包不完整或结果校验失败时不生成逐股重跑建议。

导出后自动运行[离线完整性校验](verify-research-package.md)。校验失败的 ZIP 不作为 `research.zip` 上传，验证结果仍可用于排查。完整性通过仅说明 ZIP 与自带清单一致，不证明来源、日历或研究结论真实。

部分或全部股票失败时，仍保留通过完整性检查的诊断包，工作流显示失败；应先查看入口页里的失败原因。日历失败、输入不合法、依赖安装失败或运行超时时，可能没有研究 ZIP。工作流最长运行 12 分钟，中断或超时不保证保留产物。

本工作流仅手动触发，不设置定时或 PR 联网执行，不使用付费模型、不连接券商、不修改仓库。GitHub Actions 运行资源和 artifact 存储仍计入账号相应额度。所有数据来源保持未核验；新浪日历用于 SS/SZ 是未核验假设，不代表交易所或独立来源认证。

希望本地运行时，使用[快捷研究命令](quick-market-research.md)。
