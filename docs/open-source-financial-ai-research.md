## 2. 调研观察

### TradingAgents
公开 README 描述了基本面、情绪、新闻和技术分析角色，之后由多空研究员辩论，再交由交易与风险角色综合。其价值在于角色边界和反方质询。局限是多 Agent 一致并不等于事实正确；需要独立行情/财务证据和确定性计算验证。

### FinRobot
公开 README 强调模型推理与程序确定性计算分离，并描述多阶段研究、估值和报告工作流。该原则适合本项目：价格、财务比率、估值输入、收益率、回撤等数值必须由有测试的代码计算；LLM 只能解释已计算结果和指出证据缺口。

### Qlib
公开 README 将其定位为 AI 量化研究平台，并描述 Point-in-Time 数据、模型和回测能力。适合借鉴历史可得性、实验复现、数据集/模型版本绑定。接入前需审计数据许可、市场覆盖、复权口径和本项目现有数据适配器。

### RD-Agent
公开 README 将其定位为自动化数据/模型研发流程，Qlib 文档亦指向其量化因子研究用途。适合借鉴“提出假设—运行实验—按预先定义指标评估—保存实验记录”的闭环；不能让模型自行更改验收标准或选择性报告结果。

### FinRL
当前 README 将原始仓库定位为教育、研究和原型用途，并指向后续 FinRL-X 仓库。故本项目只把它作为研究评估范式参考，不直接依赖旧仓库作为生产运行时。

## 3. 对 stock-market-Agent 的落地架构

采用分层而非整仓复制：

1. 数据与证据层：沿用已有来源适配器、来源时间戳、证据包和财务声明校验。
2. 确定性计算层：沿用现有指标、趋势、财务质量和回测代码；所有数值需有单元测试和来源口径。
3. 金融审核预检层：使用 `financial_ai_review_rules.py` 对改动文件分类并生成检查项。
4. AI 审核上下文层：使用 `financial_ai_review_context.py` 将分类、启发式命中和核查要求整理为有界 JSON 上下文。
5. 专项审核角色层：后续按数据、基本面、技术指标、回测、风险五类角色拆分，角色输出必须引用文件/数据证据。
6. 综合裁决层：只汇总事实、推断、冲突和缺失证据；证据不足必须标记 uncertain。
7. 报告层：沿用简明中文核心结论、时间序列折线图、数据来源和风险说明。

## 4. 二次开发路线

- F1：金融路径分级、启发式风险提示和有界 AI 上下文（本 PR）。
- F2：把金融上下文安全地接入现有 AI reviewer；模型输入仍绑定 PR head SHA 和可信 diff。
- F3：增加结构化多角色输出 schema，逐项要求证据位置、事实/推断区分和不确定性。
- F4：为财务指标、技术指标、复权、回测偏差和风险指标建立确定性 oracle 测试。
- F5：使用冻结历史样本做离线回放，评估误报、漏报、证据引用准确率和跨版本稳定性。
- F6：再考虑受控的研究实验自动化；实验不得连接券商、提交订单或使用真实账户。

## 5. 验收指标

- AI 结论可追溯到文件、数据记录或测试输出。
- 财务和行情数值来自确定性代码，不由模型心算或编造。
- 历史研究严格遵守公告发布时间和可得时间，防止未来数据泄漏。
- 每个 Agent 的输出结构化且可独立测试；综合 Agent 不得覆盖或删除反对证据。
- 离线测试可重复，不依赖外部模型或网络。
- 对缺失、冲突和未核验来源明确降级，不输出确定性收益承诺。
- 此审核系统不连接券商、不交易、不授予模型合并权限。
